# OUK Help Bot

Telegram-бот для приемной кампании: регистрация, сбор перечня документов, модерация заявок и управление доступами сотрудников.

## Архитектура

Проект организован в одной структуре в корне репозитория:

- `main.py` и `loader.py`: точка входа и инициализация.
- `handlers/*`: Telegram-слой (оркестрация событий).
- `services/*`: бизнес-операции и интеграции.
- `core/*`: конфиг, ресурсы и callback-константы.
- `middlewares/*`, `states/*`: инфраструктура FSM/middleware.
- `keyboards/*`: inline/reply клавиатуры.
- `data/*`: файловые хранилища (`JSON`, `Excel`, audit-log, локальные документы).

Ключевые сценарии:

- `handlers/registration.py`: анкета и модерация регистраций.
- `handlers/documents.py`: пошаговая отправка перечня документов, калькулятор скидок, модерация пакетов.
- `services/notifier.py`: уведомления ответственным и в чат приемной комиссии.
- `services/excel_registry.py`: upsert в Excel-реестры (аккаунты и абитуриенты).
- `services/access_control.py`: права сотрудников (уведомления, модерация, админ, специальности/группы).
- `services/support_tickets.py`: единый lifecycle тикетов поддержки (создание, ответы, блокировки, SLA-пинги, автозакрытие).
- `core/resources/text_file/catalog.py`: раздельные каталоги `uni`/`college` и общие helper-функции.
- `core/resources/text_file/pricing.py`: раздельные льготы `uni`/`college` (двуязычно) с единым API.

## Запуск

```bash
python main.py
```

## Что делает бот

- Регистрация пользователя с проверкой ФИО, телефона и роли.
- Отправка перечня документов в приемную комиссию.
- Отдельные сценарии для `Университет` и `Колледж` в главном меню.
- Нумерация повторных попыток отправки анкеты/перечня в уведомлениях.
- Индикация статуса Excel в служебных уведомлениях:
  - `📒 Excel ранее: ✅/❌` — запись уже была или нет;
  - `💾 Excel запись: ✅/❌` — удалось ли зафиксировать запись.
- Модерация заявок ответственными сотрудниками.
- Централизованное управление правами доступа администратором.
- В разделе помощи убран FAQ, а в пункте «Вопрос университету» добавлена прямая ссылка на блог ректора.

## Колледж

- Раздел колледжа теперь имеет отдельное меню (`О колледже`, `Специальности`, `Регистрация`, `Перечень документов`, `Локация`, `Соцсети`) вместо заглушки.
- Информационный экран `О колледже` вынесен в централизованные локализованные тексты (`MESSAGES`), как и университетские разделы.
- Общие функции (локация, соцсети, каталог направлений) переиспользуются без дублирования кода.
- Специальности и скидки для колледжа вынесены в отдельные структуры данных и редактируются независимо от университета.
- Для колледжа добавлены отдельные контакты/соцсети и отдельный маршрут возврата в меню колледжа.
- Для колледжа используется отдельный перечень требуемых документов (без шага ЕНТ), а перед отправкой обязательно запрашивается источник.

## Переменные окружения (важное)

- `BOT_TOKEN` — токен Telegram-бота.
- `ADMIN_ID` — Telegram ID главного администратора.
- `PRIEMKA_ID` — чат/пользователь приемной комиссии (fallback для модерации).
- `REVIEW_CHAT_ID` — чат модерации (опционально).
- `PSYCHOLOG_CHAT_ID` — чат психологической поддержки.
- `PSYCHOLOG_ADMIN_ID` — ID администратора психологического модуля (статистика/назначения).
- `BOT_PROXY_URL` — прокси для доступа к Telegram API (опционально), пример:
  - `http://user:pass@host:port`
  - `socks5://user:pass@host:port`
- `EXCEL_PATH` — путь к основному Excel реестру абитуриентов.
- `FALLBACK_EXCEL_PATH` — fallback-путь, если основной Excel заблокирован.
- `ACCOUNTS_PATH` — путь к Excel реестру аккаунтов.
- `FALLBACK_ACCOUNTS_PATH` — fallback для Excel аккаунтов.
- `COLLEGE_EXCEL_PATH` — путь к Excel-реестру абитуриентов колледжа.
- `FALLBACK_COLLEGE_EXCEL_PATH` — fallback-путь для реестра абитуриентов колледжа.
- `COLLEGE_ACCOUNTS_PATH` — путь к Excel-реестру аккаунтов колледжа.
- `FALLBACK_COLLEGE_ACCOUNTS_PATH` — fallback для Excel аккаунтов колледжа.

Важно по форматам путей:

- рекомендуемый формат: `data/admissions_registry.xlsx`;
- допускается ввод вида `Path("data/admissions_registry.xlsx")` — конфиг нормализует его автоматически.

## Безопасность и приватность

- Не храните реальный `BOT_TOKEN` в репозитории и скриншотах. При утечке сразу ротируйте токен у `@BotFather`.
- Для персональных данных используйте команды `/my_data` и `/delete_me`.
- Бот маскирует чувствительные данные в fallback-уведомлениях об ошибках доставки.
- Если основной Excel заблокирован, запись идет в fallback-файл, чтобы не терять данные.
- Чаты поддержки теперь учитывают частично настроенные переменные окружения безопасно (без падения при пустом `PSYCHOLOG_CHAT_ID`).

## Excel (универ/колледж)

- Реестры разделены по трекам: университет и колледж пишутся в разные Excel-файлы.
- Заголовки в таблицах переведены на русский для сотрудников.
- В таблице аккаунтов добавлен столбец `Грантник` (булев флаг).
- Флаг `Грантник` можно переключать прямо в админ-панели бота.
- Для листов применяется автоформат: автоширина колонок, фильтры и закрепление шапки.
- Автосортировка в аккаунтах:
  - сначала студенты/выпускники (обычные -> грантники),
  - затем 3 пустые строки,
  - потом преподаватели/работники (обычные -> грантники),
  - внутри блока сортировка по кафедре/специальности/группе/ФИО.

## Устойчивость к сетевым сбоям

На старте бот выполняет `delete_webhook` с retry-механизмом:

- `STARTUP_MAX_RETRIES` — максимум попыток,
- `STARTUP_RETRY_DELAY_SECONDS` — пауза между попытками.

Это защищает деплой от временных проблем сети/маршрутизации до `api.telegram.org`.

## Антиспам

- Антиспам действует на финальные действия (`отправка анкеты`, `отправка перечня`, `подтверждение обращения`).
- Таймаут: **1 час** на каждое действие отдельно (ключ: `user_id + action`).
- Повторный клик во время выполнения того же действия блокируется как `in_progress`.

## Админ: управление доступами

Панель `⚙️ Управление доступами`:

- `🔔 Уведомления` — сотрудник получает уведомления о новых регистрациях для назначенных направлений.
- `✅ Модерация` — сотрудник может открывать заявки и подтверждать/отклонять.
- `👑 Админ права` — доступ к панели управления доступами и изменению ролей.
- `🎓 Назначить специальности` — выбор образовательных программ, по которым сотрудник может модерировать, с выбором уровня (`Университет`/`Колледж`).
- `🧩 Назначить группы` — инлайн-выбор групп с чекбоксами и выбором уровня (`Университет`/`Колледж`).
- Назначение групп сотруднику фильтруется по уже выданным сотруднику специальностям.
- Добавлен полный inline CRUD групп: создание/редактирование/удаление с пошаговым выбором `уровень -> кафедра -> специальность -> курс`.
- `/set_faculties <user_id> <кафедра1,кафедра2|*>` — назначение доступа по кафедрам.
- `/set_groups <user_id> <группа1,группа2|*>` — назначение доступа по группам.
- `/create_group <uni|college>|<кафедра>|<специальность>|<курс>|<группа>` — создание группы для инлайн-выбора в анкете.
- Флаг `Грантник` сохранен в реестрах, но убран из панели выдачи доступов сотрудникам.

## Порядок отправки документов

- Источник (`откуда узнали`) теперь запрашивается в самом конце перед финальной отправкой пакета.
- Подтверждение отправки показывается только после ввода источника.
- Это сокращает ранние отказы и уменьшает количество прерванных сценариев на старте.

## Психологическая поддержка: метрики

- Кнопка `📊 Статистика психологов` и команда `/psy_stats` доступны участникам чата психологов.
- Вне чата психологов статистика недоступна.
- В психочате можно включить reply-клавиатуру статистики командой `/psy_kb`.
- Для просмотра статистики психологов доступна команда `/psy_stats` (только в психочате).
- Доступны фильтры: день/неделя/месяц/год/все время.
- Качество работы учитывает несколько факторов:
  - пользовательская оценка,
  - количество ответов,
  - скорость первого ответа,
  - факт закрытия тикета пользователем.
- Психо-админ может назначить тикет конкретному психологу из инлайн-кнопок в карточке тикета.
- Реестр психологов автоматически пополняется активными участниками чата психологов.
