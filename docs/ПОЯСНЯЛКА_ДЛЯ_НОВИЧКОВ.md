# Пояснялка для новичков (с нуля)

Этот файл написан для человека, который:

- впервые видит Python;
- не работал с Telegram-ботами;
- не знает архитектуру проекта.

Цель: быстро понять, **что где находится**, **как это работает**, **как безопасно менять код**.

## 1) Что это за проект

`OUK Help Bot` — Telegram-бот для:

- регистрации абитуриента;
- отправки перечня документов;
- модерации заявок;
- управления доступами сотрудников;
- психологической поддержки (тикеты и статистика).

Проект поддерживает 2 трека:

- `uni` — университет;
- `college` — колледж.

Они разделены по данным, меню и Excel-реестрам.

## 2) Как устроен проект (очень просто)

- `main.py` — точка входа (старт приложения).
- `handlers/` — реакции на кнопки/сообщения Telegram.
- `services/` — бизнес-логика (расчеты, хранение, уведомления).
- `keyboards/` — кнопки (inline/reply).
- `core/` — конфиг, тексты, callback-константы.
- `utils/` — небольшие общие функции (валидация, форматирование и т.д.).
- `utils/safe_telegram.py` — `edit_or_send_text` (после фото/медиа шлёт новое сообщение), подавление `message is not modified`.
- `core/database_dsn.py` — разбор `DB_URL` для Railway в DSN async/sync.
- `utils/main_menu_reply.py` — одно якорное сообщение для reply-клавиатуры главного меню.
- `states/` — FSM-состояния (этапы диалогов).
- `data/` — Excel-реестры и файлы документов; при первом запуске возможен одноразовый импорт из `data/*.json` в PostgreSQL.
- `db/` — модели SQLAlchemy, репозитории, миграции Alembic.

Правило:  
**handlers управляют потоком**,  
**services делают работу**,  
**utils дают мелкие переиспользуемые функции**.

## 2.5) Почему после «Главное меню» не «залипает» анкета

При входе в главное меню (`LEVEL_UNI` / `LEVEL_COLL` / текст «Главное меню») вызывается `reset_user_wizard_for_main_menu` из `services/fsm_scope.py`: очищается FSM и черновики сценариев, но сохраняются язык, трек (универ/колледж), привязка reply-клавиатуры и открытый психо-тикет (если был). Обычные сообщения снова обрабатываются общими хендлерами.

## 3) Что такое FSM и зачем она нужна

FSM (Finite State Machine) = «бот помнит, на каком шаге пользователь».

Пример:

1. бот просит ФИО;
2. потом телефон;
3. потом специальность;
4. потом документы.

Если бы FSM не было, бот «забывал» бы этап и путался.

## 4) Как проходит регистрация

Ключевой файл: `handlers/registration.py`.

Поток:

1. выбор уровня (`uni/college`);
2. сбор личных данных;
3. сохранение в pending;
4. отправка на модерацию;
5. после одобрения — запись в Excel аккаунтов.

Важно:

- запись идет в отдельные Excel для `uni` и `college`;
- доступны ACL-права (кто что видит и модерирует).

## 5) Как проходит отправка перечня документов

Ключевой файл: `handlers/documents.py`.

Поток:

1. если нет ФИО/телефона — бот запрашивает;
2. выбор направления поступления;
3. загрузка документов;
4. запрос источника («откуда узнали»);
5. отправка пакета в модерацию.

Важно:

- у колледжа и университета различается список и логика шагов;
- возврат в меню должен вести в корректный трек (`LEVEL_COLL` / `LEVEL_UNI`).

## 6) Где менять тексты и кнопки

- Тексты: `core/resources/text_file/texts.py`
- Подписи кнопок: `core/resources/text_file/menus.py`
- Inline-клавиатуры: `keyboards/inline/*.py`
- Reply-клавиатуры: `keyboards/reply/*.py`

Если меняете кнопку, проверьте:

1. callback-константу в `core/callbacks.py`;
2. handler, который ловит этот callback.

## 7) Зачем вынесены сервисы

Пример: `services/notifier.py`.

Плюсы:

- не дублируем отправку сообщений в каждом handler;
- проще тестировать;
- проще менять формат уведомлений централизованно.

Это и есть DRY: **Don’t Repeat Yourself**.

## 8) Почему важны utils

В проекте есть `utils/number_format.py`:

- `format_int(450000) -> "450,000"`

Зачем:

- единый стиль отображения чисел;
- не нужно в каждом месте вручную форматировать строку;
- меньше багов и дубликатов.

## 9) Безопасность (базовые правила)

1. Никогда не коммить `.env` и токены.
2. Любой ввод пользователя валидировать (`utils/validators.py`).
3. В логах не печатать лишние персональные данные.
4. Для анонимных идентификаторов использовать криптостойкие методы.
5. При ошибках — аккуратный fallback, а не падение процесса.

## 10) Как добавлять новую фичу правильно

Простой чеклист:

1. Добавить callback в `core/callbacks.py` (если нужна кнопка).
2. Добавить кнопку в `keyboards/...`.
3. Добавить handler в `handlers/...`.
4. Вынести повторяемую логику в `services/...` или `utils/...`.
5. Добавить/обновить тексты RU/KZ.
6. Прогнать тесты и проверить линтер.
7. Обновить `README.md` и `TECH_DOCS.md`.

## 11) Как читать ошибки traceback

В traceback важны 3 вещи:

- файл;
- строка;
- текст ошибки.

Пример:
`TypeError: get_all_specialties() got an unexpected keyword argument 'track'`

Смысл: функция вызвана с аргументом `track`, но ее сигнатура это не поддерживает.  
Лечение: синхронизировать сигнатуру функции и места вызова.

## 12) Мини-словарь терминов

- **Handler** — функция-обработчик события Telegram.
- **Service** — бизнес-логика без привязки к Telegram-событию.
- **CallbackData** — строковый идентификатор нажатой inline-кнопки.
- **FSM state** — текущее состояние пользователя в диалоге.
- **ACL** — управление правами доступа.
- **Refactor** — улучшение структуры кода без изменения бизнес-смысла.

## 13) Что делать, если страшно менять код

Рабочая стратегия:

1. Делай маленькие изменения.
2. После каждого шага запускай тесты.
3. Не меняй сразу 10 файлов без проверки.
4. Сначала читай существующий паттерн, потом копируй стиль.
5. Любую магию выноси в именованную функцию с понятным названием.

## 14) Главный принцип проекта

Код должен быть понятен «следующему человеку», а не только автору.

Если сомневаешься:

- выбери более явный вариант;
- добавь короткий комментарий «почему», а не «что»;
- избегай дублирования.

## 15) Практические примеры из проекта

### Статистика психологов

- Команды: `/psy_stats` и `/check_stats`.
- Они работают только в чате психологов (`PSYCHOLOG_CHAT_ID`).
- Если команда «молчит», проверь, не перехватывает ли ее более общий handler.

### Почему бывает «Тикет не найден»

В проекте могут встречаться такие формы ID тикета:

- `10013`
- `#10013`
- `ticket_10013`
- `#ticket_10013`

Правильный подход:

1. Нормализовать ticket_id (убрать `#`, `ticket`*, `#ticket`*).
2. Для callback использовать устойчивый разбор (`rpartition`).
3. Добавить fallback: извлечь цифры и повторить поиск.

Это и есть «защитный код»: он учитывает реальные вариации данных.

### Почему бывает `BUTTON_DATA_INVALID`

Telegram ругается, когда в `callback_data`:

- слишком длинная строка;
- или строка содержит «неожиданные» символы/форматы (например, `#ticket_10014` вместо просто `10014`).

Чтобы не ловить такие ошибки, в проекте нормализуем `ticket_id` до **только цифр**
перед формированием callback-data (см. `keyboards/inline/menu.py`).

## 16) Рассылки и личный кабинет

- Таргетированная рассылка по базе: `handlers/broadcast_flow.py`, `services/broadcast_scope.py` (право `can_broadcast` в админ-панели).
- **Рабочее место** (`handlers/staff_cabinet.py`, кнопки `keyboards/inline/workplace.py`): для сотрудников с `can_review` — заявки, уведомления, расписание, мероприятия, смена группы. Уведомления: фильтры `wpfil_*`, можно «Без фильтра спец.»; ссылка строкой `LINK: https://...`.
- Расписание — **фото на неделю** (`group_schedule_photos`, `services/staff_schedule.py`). Staff смотрит по дереву кафедра→спец.→курс→группа; студент — только своё.
- Смена группы: `StaffCabinetFlow` → обновление в БД и `upsert_registration_account_record` в Excel.
- Модерация из рабочего места вызывает те же handlers, что админ-панель (`registration.review_registrations`), но кнопка «Назад» ведёт в `cabinet_workplace` (через `review_back_callback` в FSM).

## 17) Excel-реестры

Файл: `services/excel_registry.py`.

| Файл | Назначение |
|------|------------|
| `data/accounts_registry.xlsx` / college-аналог | Студенты, выпускники |
| `data/staff_registry.xlsx` / `college_staff_registry.xlsx` | Только работники и преподаватели |
| реестры абитуриентов | Пакеты документов |

Правила:

- **Одна строка на Telegram ID** — при повторном изменении данных строка обновляется, новая не создаётся.
- Колонка **«Грантник»**: значения `Да` / `Нет`, в Excel — выпадающий список (два клика).
- **Сортировка** аккаунтов: роль (студент → выпускник → работник/препод), внутри роли грантники выше, затем кафедра/спец/группа/ФИО; блок сотрудников отделён пустыми строками.
- **Суммы** в реестре абитуриентов отображаются с разделителем тысяч (например `450,000` в ячейке Excel).

Полная синхронизация с БД (удаляет «мёртвые» строки): `python scripts/sync_excel.py` или автоматически при старте бота (`EXCEL_SYNC_ON_STARTUP`).

## 18) Вопрос колледжу (WhatsApp)

В треке колледжа, раздел помощи «университет/колледж»: вместо блога ректора показывается inline-кнопка на WhatsApp.

- URL: `settings.college_whatsapp_url` (`core/config.py`, по умолчанию `https://wa.me/77028429302`).
- Клавиатура: `get_college_whatsapp_kb` в `keyboards/inline/menu.py`.

## 19) DB_URL — это не «новая база»

`DB_URL` (или `DATABASE_URL`) — **только адрес вашей текущей PostgreSQL**.  
Регистрации, документы, ACL **не пересоздаются** при смене URL или деплое.

```env
DB_URL=postgresql://user:pass@host:5432/oukhelpbot
```

- Бот при старте: `SELECT 1` (жив ли сервер).
- `DB_AUTO_CREATE_TABLES=false` по умолчанию — таблицы сами не трогаем.
- Нужна новая таблица из свежего кода → один раз `alembic upgrade head` (добавляет, не удаляет строки).
- Импорт `data/*.json` — только если в БД ещё нет ни одной регистрации.

Локально вместо URL: `DB_HOST`, `DB_USER`, `DB_PASS`, `DB_NAME`.
