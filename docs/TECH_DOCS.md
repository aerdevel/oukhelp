# Техническая документация OUK Help Bot

## Потоки данных

- Пользователь проходит FSM-сценарий в `handlers/*`.
- Данные нормализуются и валидируются в `utils/validators.py` (телефон KZ, `sanitize_text`, минимальные длины для ФИО/источника/текста помощи/комментария к оценке).
- Черновики и статусы модерации сохраняются в `data/*.json` через `services/*_store.py`.
- Итоговые и промежуточные данные пишутся в Excel через `services/excel_registry.py`.
- Ответственные сотрудники получают уведомления через `services/notifier.py`.
- Тикеты поддержки проходят централизованный lifecycle через `services/support_tickets.py`.
- Для абитуриентов добавлен `admission_track` (`uni`/`college`), который управляет каталогами, льготами и Excel-реестрами.

## Главное меню, FSM и Telegram edge cases

- `services/fsm_scope.reset_user_wizard_for_main_menu` — сброс анкеты/документов/калькулятора при входе в главное меню с белым списком полей (язык, трек, якорь reply-клавиатуры, психо-тикет).
- `utils/main_menu_reply.sync_main_menu_reply_keyboard` — не плодит новые служебные сообщения: обновляет одно якорное сообщение с reply-клавиатурой.
- `utils/safe_telegram.safe_edit_message_text` — подавляет штатную ошибку `message is not modified` при повторных `edit_text` (калькулятор и др.).

## Регистрация

Основной файл: `handlers/registration.py`.

Этапы:

- Сбор ФИО -> телефона -> роли -> кафедры/бірлестік и специальности -> группы/курса.
- Финальное подтверждение вызывает `add_pending_registration`.
- Для каждой повторной отправки выставляется `submit_attempt` (начиная с 1).
- Перед отправкой номера выполняется проверка владельца:
  - тот же `tg_user_id` — разрешено;
  - другой пользователь — отклонение с подсказкой.
- После `upsert_registration_account_record` в уведомление ответственным уходит:
  - номер попытки;
  - признак, была ли запись в Excel ранее (`✅/❌`);
  - признак успешной записи в Excel (`✅/❌`).

## Перечень документов

Основной файл: `handlers/documents.py`.

Этапы:

- Сбор недостающих анкеты/телефона.
- Выбор факультета и специальности поступления.
- Последовательная загрузка документов.
- Подтверждение согласия на обработку ПД.
- Финальный шаг: источник (`откуда узнали`) перед отправкой.
- Кнопки подтверждения отправки отображаются после ввода источника.
- Сохранение пакета в pending + запись в Excel (status=pending) + отправка в чат модерации.

Особенности:

- Для повторных отправок пакета ведется `submit_attempt`.
- В карточке пакета в чате модерации показывается статус Excel (`✅/❌`).
- При ошибке отправки в чат модерации бот делает безопасный fallback-алерт админу.

## Excel слой

Файл: `services/excel_registry.py`.

`upsert_*` теперь возвращают структурный результат:

- `ok`: запись выполнена;
- `path`: куда сохранено;
- `is_fallback`: использован fallback-файл;
- `was_existing`: строка уже была до upsert.

Это позволяет явно подтверждать факт дублирования/обновления данных в служебных уведомлениях.

Дополнительно:

- Раздельные файлы Excel для университета и колледжа:
  - абитуриенты: `EXCEL_PATH` / `COLLEGE_EXCEL_PATH`,
  - аккаунты: `ACCOUNTS_PATH` / `COLLEGE_ACCOUNTS_PATH`.
- Заголовки таблиц русифицированы для сотрудников.
- Таблица аккаунтов:
  - добавлен столбец `Грантник` (bool),
  - применяется сортировка (обычные -> грантники, внутри по кафедре/специальности/группе/ФИО),
  - студенты/выпускники сверху, работники/преподаватели снизу, между блоками 3 пустые строки,
  - включен автоформат (ширина колонок, фильтры, закрепленная шапка).

## Управление доступом

Файл: `services/access_control.py` + UI в `handlers/registration.py`.

Кнопки админа:

- `Уведомления` (`can_notify`) — получать новые входящие заявки.
- `Модерация` (`can_review`) — открывать и обрабатывать заявки/пакеты.
- `Рассылка по базе` (`can_broadcast`) — таргетированная рассылка по одобренным аккаунтам (кнопка в админ-панели; не-админы с флагом открывают тот же сценарий из «Мой кабинет»).
- `Админ права` (`is_admin`) — полный доступ к панели прав.
- `Назначить специальности` (`specialties`) — ограничение области модерации.
- Перед выбором специальностей админ выбирает уровень (`uni`/`college`), чтобы не смешивать каталоги.
- Назначение групп реализовано через инлайн-кнопки с чекбоксами, пагинацией и выбором трека (`uni`/`college`).
- Назначение групп ограничено доверенными специальностями сотрудника (курс не используется как ACL-ограничитель).
- Добавлен отдельный контур админ-панели для управления справочником групп (CRUD) без slash-команд.
- `Грантник` исключен из UI панели доступов сотрудников, но сохраняется в реестрах Excel/JSON.

## Таргетированные рассылки и ЛК ответственного

- Логика фильтрации и доставки: `services/broadcast_scope.py` (`filter_approved_users`, `recipients_for_reviewer`, `split_body_and_link`, `deliver_text_broadcast`).
- Хендлеры мастера рассылки: `handlers/broadcast_flow.py`, состояние `BroadcastFlow.waiting_message` в `states/states.py`.
- Админ и пользователи с `can_broadcast` проходят сценарий с инлайн-фильтрами (трек, роль); ответственные с `can_review` (и админ) из «Мой кабинет» могут отправить текст только подопечным по ACL (`recipients_for_reviewer`).
- Опциональная кнопка-ссылка: отдельная строка в конце текста `LINK: https://...` (только `http`/`https`).
- Смена группы одобренному студенту: `handlers/staff_cabinet.py` + `StaffCabinetFlow`, обновление JSON через `update_approved_profile` и синхронизация строки аккаунта в Excel через `upsert_registration_account_record`.

## Поддержка и безопасность

Основные файлы: `handlers/common.py`, `services/support_tickets.py`, `services/support_transport.py`.

Ключевые решения:

- Безопасный выбор рабочих чатов поддержки: обработчик ответов сотрудников не падает, если `PSYCHOLOG_CHAT_ID` не задан.
- Идентификаторы анонимных пользователей генерируются через криптостойкий источник (`secrets`) вместо псевдослучайного генератора.
- Парсинг времени (`ISO`) и пересчет SLA вынесены в общие утилиты, чтобы избежать дублирования и расхождения логики.
- SLA-константы (`24ч` пинги и `48ч` автозакрытие) централизованы в одном месте сервиса.
- Добавлена агрегированная статистика психологов с фильтрами периодов и расчетом quality score.
- Поддерживается assignment тикета конкретному психологу через инлайн-кнопки.
- Статистика доступна только в чате психологов.
- Статистика вызывается командой `/psy_stats` (без алиасов, чтобы не плодить дубликаты).
- Реестр психологов автоматически пополняется активными участниками чата психологов по входящим сообщениям.
- Для стабильного назначения психолога callback-парсинг выполняется справа (`rpartition`), чтобы не терять ticket_id.

Формула quality score (упрощенно):

- баллы за оценку пользователя,
- баллы за количество ответов,
- бонус за скорость первого ответа,
- бонус за закрытие пользователем.

## ACL: 3 уровня

Файл: `services/access_control.py`.

Доступы проверяются в порядке:

- специальность,
- кафедра / бірлестік (в JSON по-прежнему ключ `faculties`, но для колледжа сюда попадают названия объединений из `catalog.py`),
- группа.

Админ-команды:

- `/set_faculties`,
- `/set_groups`,
- `/create_group` (через `services/study_groups.py` для инлайн-выбора группы в регистрации).

## Раздел колледжа

Основные файлы: `handlers/common.py`, `handlers/info.py`, `core/resources/text_file/texts.py`, `keyboards/inline/menu.py`.

Что реализовано:

- Вместо заглушки добавлено отдельное меню колледжа с переиспользованием общих кнопок и callback-структуры.
- В меню колледжа добавлены прямые входы в регистрацию и отправку перечня документов.
- Контент `О колледже` локализован и хранится в `MESSAGES`.
- Переиспользуются существующие разделы (`Специальности`, `Локация`, `Соцсети`) без дублирования бизнес-логики.
- Каталог специальностей и льгот колледжа вынесен в отдельные словари, но используется теми же handler-потоками, что и университет.
- Добавлены отдельные соцсети/контакты для колледжа и отдельный возврат в меню колледжа из инфо-разделов.
- Для колледжа используется отдельный чек-лист документов (без шага ЕНТ), а возврат из «В главное меню» сохраняет трек.

## Рекомендации по развитию

- Перейти с JSON-хранилищ на транзакционную БД (`SQLite/PostgreSQL`) для устранения race condition.
- Добавить интеграционные тесты для `contact` и повторных отправок.
- Добавить скрипт ротации секретов и шаблон `env.example` без реальных токенов.
