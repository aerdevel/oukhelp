# Сценарий презентации OUK Help Bot (колледж, 3 участника)

Длительность: **12–15 минут**. Аудитория: приёмная, кураторы, администрация колледжа.

Роли:

| Участник | Роль в сценарии | Telegram-аккаунт |
|----------|-----------------|------------------|
| **А** | Абитуриент / студент колледжа | личный |
| **Б** | Куратор (модератор, `can_review`) | служебный |
| **В** | Администратор / приёмная | `ADMIN_ID` или `PRIEMKA_ID` |

Подготовка (за 10 минут до выступления):

1. `alembic upgrade head`, бот запущен, в `.env` указаны `BOT_TOKEN`, `DB_*`, `PRIEMKA_ID`.
2. У участника **Б** в админ-панели: право **Модерация** (`can_review`), ACL на тестовую группу (или `*`).
3. Закрыть Excel-файлы на ПК демонстратора (или синхронизация уйдёт в `*_fallback.xlsx`).
4. При необходимости: `python scripts/sync_excel.py` — актуальные реестры из БД.

---

## Блок 1 — Вход и трек колледжа (А, ~3 мин)

**А** открывает бота, `/start`.

1. Выбор языка (RU/KZ).
2. **Колледж** → главное меню колледжа.
3. Кратко показать: калькулятор, регистрация, документы, помощь.
4. **Помощь** → «Вопрос колледжу» → inline-кнопка **WhatsApp** (`https://wa.me/77028429302`) — без копирования номера вручную.

Реплика ведущего: «Один бот — два трека; колледж не смешивается с университетом в данных и Excel».

---

## Блок 2 — Регистрация и модерация (А + Б, ~4 мин)

**А**: Регистрация → роль **Студент** → ФИО, телефон, кафедра/спец/курс/группа → отправка.

**Б**: Личный кабинет → **Рабочее место** → **Заявки на регистрацию**.

1. Открыть заявку **А**, одобрить.
2. Показать кнопку **Назад** — возврат в рабочее место (не в глобальную админ-панель).

**В** (опционально): та же заявка видна в админ-панели — единый поток модерации.

Реплика: «Модератор работает из кабинета, админ — из панели; правила ACL одни».

---

## Блок 3 — Документы и Excel (А + В, ~3 мин)

**А**: Перечень документов → загрузка 1–2 файлов → источник «откуда узнали» → отправка.

**В**: модерация пакета в чате приёмки / админке → одобрение.

На проекторе открыть (после sync):

- `data/college_admissions_registry.xlsx` — абитуриенты;
- `data/college_accounts_registry.xlsx` — аккаунты, колонка **Грантник** (список Да/Нет);
- `data/college_staff_registry.xlsx` — только работники/препод.

Показать: одна строка на Telegram ID; сортировка по роли; суммы с разделителем тысяч.

Реплика: «БД — источник правды; Excel пересобирается при старте и командой `scripts/sync_excel.py`».

---

## Блок 4 — Рабочее место: уведомления и мероприятие (Б, ~3 мин)

**Б**: Рабочее место → **Уведомление студентам**.

1. Фильтр: трек **колледж**, роль **студент**, **Без фильтра спец.** → Готово.
2. Текст: «Завтра консультация в 10:00» + строка `LINK: https://example.kz/event`

**А** получает сообщение с кнопкой **Открыть**.

**Б**: **Мероприятие** — короткий анонс с той же схемой `LINK:` (кнопка «Подробнее»).

Реплика: «Рассылка только по ACL; ссылка не вставляется в текст, а в безопасную URL-кнопку».

---

## Блок 5 — Расписание и смена группы (Б + А, ~2 мин)

**Б**: Расписание → **Добавить пару** → группа **А** → день → время → предмет → аудитория.

**Б**: **Просмотр расписания** (все свои группы) → **Отправить расписание группам**.

**Б**: **Сменить группу** → ввести Telegram ID **А** → новая группа → **А** получает уведомление.

---

## Финал (~1 мин)

- Безопасность: PostgreSQL, маскирование телефонов/usernames в логах, без HTML parse mode.
- Масштаб: новые таблицы через Alembic, бизнес-логика в `services/`, не в handlers.

Вопросы аудитории.

---

## Запасные сценарии (если что-то упало)

| Проблема | Действие |
|---------|----------|
| Excel не обновился | `python scripts/sync_excel.py` |
| Бот не стартует | проверить `mask_username` / зависимости: `pip install -r requirements.txt` |
| Нет заявок у **Б** | выдать `can_review` и группу в ACL |
| WhatsApp не открывается | проверить `COLLEGE_WHATSAPP_URL` в `.env` |
