# OUK Help Bot — Толық техникалық құжаттама (KZ)

## 1. Жобаның мақсаты

`OUK Help Bot` — талапкерлерді қабылдау үдерісін автоматтандыратын Telegram-бот:

- талапкер анкетасын жинау,
- құжаттарды кезең-кезеңімен қабылдау,
- жауапты қызметкерлер арқылы модерация,
- дербес деректерге қатысты базалық талаптарды орындау,
- процесті бақылау (статус, аудит, кезек).

Бұл құжат жаңа әзірлеушілерге арналған: жобаны тез түсініп, қауіпсіз өзгеріс енгізуге көмектеседі.

---

## 2. Жұмыс архитектурасы

Негізгі ағын:
`Telegram Update -> Handler -> Service -> Store/Infra -> Жауап/Хабарлама`

Қабаттар:

1. Интерфейс қабаты (`handlers`, `keyboards`, `states`)
2. Бизнес-логика (`services`)
3. Инфрақұрылым (`utils`, файл, Excel)
4. Конфигурация (`core/config.py`, `.env`)

---

## 3. Негізгі файлдар және жауапкершілік

## 3.1 Іске қосу

- `main.py`
  - логгерді іске қосады,
  - retention cleanup орындайды,
  - polling бастайды.
- `loader.py`
  - `Bot` пен `Dispatcher` құрады,
  - middleware және router қосады.
- `core/config.py`
  - `.env` арқылы параметрлерді оқиды.

## 3.1.1 Бірнеше админ (ADMIN_ID/ADMIN_IDS)

- `ADMIN_ID` — негізгі (бас) админ.
- `ADMIN_IDS` — қосымша админдер (ID тізімі, үтір/бос орын арқылы).

Барлық көрсетілген ID админ ретінде танылады. Бірақ **тек бас админ** ғана басқа қолданушыларға админ құқықтарын
беруге/алып тастауға құқылы.

## 3.2 Handler модульдері

- `handlers/common.py`
  - `/start`, тіл таңдау, негізгі мәзір,
  - `/status`, `/my_data`, `/delete_me`, `/moderation_queue`.
- `handlers/registration.py`
  - анкета FSM,
  - тіркеу өтінімдерін модерациялау,
  - құқықтарды админ арқылы басқару.
- `handlers/documents.py`
  - құжаттарды жүктеу FSM,
  - ПД келісімін тексеру,
  - құжат пакетін модерациялау.

## 3.3 Service модульдері

- `registration_store.py` — анкета деректерін сақтау.
- `documents_store.py` — құжат пакеттерін сақтау.
- `access_control.py` — рөлдер мен құқықтар.
- `notifier.py` — хабарламалар тарату.
- `documents_files.py` — Telegram файлдарын серверге сақтау.
- `excel_registry.py` — Excel реестрді жаңарту.
- `status.py` — қолданушы статусы және модерация кезегі.
- `data_retention.py` — ескі pending деректерді тазалау.
- `audit_log.py` — аудит журналы.
- `user_data.py` — пайдаланушы дерегін экспорт/өшіру.

## 3.4 Utility модульдері

- `file_utils.py` — JSON қауіпсіз оқу/атомарлы жазу.
- `validators.py` — телефон тексеру, мәтін тазалау.
- `privacy.py` — сезімтал деректерді маскалау.
- `datetime_utils.py` — ISO уақыт парсингі.
- `logger.py` — лог конфигурациясы.

## 4. FSM сценарийлері

## 4.1 Анкета FSM

Кезеңдер:

1. Аты-жөні
2. Телефон
3. Рөлі
4. Кафедра/мамандық
5. Курс
6. Топ
7. Растау

Нәтиже:

- өтінім `pending` тізіміне түседі,
- жауапты тұлғаларға хабарлама жіберіледі.

## 4.2 Құжат FSM

Кезеңдер:

1. Аты-жөні (fallback),
2. Телефон (fallback),
3. Түсетін кафедраны таңдау,
4. Түсетін мамандықты таңдау,
5. Калькуляторда жеңілдіктерді таңдау және соңғы бағаны есептеу,
6. Университет туралы қайдан білгенін енгізу,
7. Аттестат/диплом,
8. Жеке куәлік,
9. 3x4 фото,
10. 075/у анықтама,
11. ҰБТ сертификаты,
12. Соңғы растау және ПД келісімі.

Нәтиже:

- файлдар серверге жүктеледі,
- пакет `pending` күйіне өтеді,
- Excel реестр жаңартылады,
- модератор чатына карточка түседі.

## 5. Дерек сақтау моделі

## 5.1 JSON файлдары

- `data/registrations.json`
  - `pending`, `approved`, `denied`.
- `data/documents_review.json`
  - `pending`, `approved`, `denied`.
- `data/access_control.json`
  - қолданушы құқықтары (`can_notify`, `can_review`, `can_broadcast`, `is_admin`, ACL сүзгілері).

## 5.2 Файл және Excel

- `data/files/<tg_user_id>/...` — құжат көшірмелері.
- `data/excel/admissions_registry.xlsx` — қабылдау реестрі.
- `data/excel/accounts_registry.xlsx` — аккаунттар реестрі (1 қолданушы = 1 жол).
- `data/audit_log.jsonl` — әрекеттер журналы.

Маңызды:

- Excel-ге `Telegram file_id` және `server_path` жазылады,
- сондықтан деректер нақты бір әзірлеушінің ноутбугіне байланбайды.

## 6. Қауіпсіздік және құпиялылық

Іске асқан мүмкіндіктер:

- құжат жібермес бұрын ПД келісімі міндетті,
- retention cleanup,
- `/my_data` және `/delete_me`,
- авариялық хабарламаларда деректерді маскалау,
- модератор әрекеттерінің аудит-ізі.

Шектеулер:

- JSON/Excel/plaintext сақтау,
- сервер деңгейіндегі шифрлау бөлек инфрақұрылымда берілуі керек.

## 7. Модерация орталығы

Мүмкіндіктер:

- екі бөлім:
  - `Өңделмеген`,
  - `Өңделген`.

  - аты-жөні,
  - статусы,

Құқықтар:

- админ — бәрін көреді,
- жауапты қызметкер — тек өзіне тиесілі топ/мамандық өтінімдерін көреді.

## 8. Cooldown (антиспам)

`middlewares/antispam.py` ішінде cooldown енді:

- `(user_id, action)` кілтімен есептеледі,
- бір әрекет екіншісін бұғаттамайды,
- финал әрекеттері үшін timeout: **1 сағат**,
- қайталама басу (`in_progress`) қорғанысы бар.

## 8.1 .env ішіндегі Excel жолы

Келесі форматтардың екеуі де қолдау табады:

- `EXCEL_PATH=data/excel/admissions_registry.xlsx`

Ұсыныс: қарапайым бірінші форматты пайдалану.

## 10. Сайт жоқ болғандағы ПД саясаты

Егер сайт болмаса:

- `PRIVACY_POLICY_URL` бос қалуы мүмкін,

Ұсыныс:

- ПД саясатының мәтінін боттың ішінде бөлек бөлім ретінде көрсету.

## 11. Хостингтен кейін деректер қайда сақталады

Деректер бот тұрған серверде сақталады:

- JSON: `data/*.json`
- Құжаттар: `data/files/...`
- Реестр: `data/excel/admissions_registry.xlsx`

Production ұсыныстары:

1. persistent disk/volume,
2. тұрақты backup,
3. `data/` директориясына шектеулі қолжетімділік.

## 12. Жаңа әзірлеушіге арналған өзгеріс чеклисті

1. Өзгерісті handler/service деңгейінде жасаңыз.
2. Callback және keyboard үйлесімділігін тексеріңіз.
3. Store құрылымы өзгерсе, миграция логикасын қосыңыз.
4. Тест қосыңыз немесе жаңартыңыз.
5. Линтер мен тесттерді жүргізіңіз.

## 14. Психологиялық қолдау (жаңа модуль)

Іске асқан мүмкіндіктер:

- аноним тикет жүйесі (`services/support_tickets.py`),
- "Психологиялық қолдау" бөлімінде тикет автоматты ашылады,
- пайдаланушы хабарламасы `PSYCHOLOG_CHAT_ID` чатына жіберіледі,
- пайдаланушыға жауап тек психолог чатында сол хабарламаға `reply` берілгенде ғана келеді,
- тикетті жабу және 1..10 баға қою бар,
- тикет ішінде психологтардың жауап статистикасы сақталады.

Қосымша:

- психолог жауап бергеннен кейін 24 сағат сайын еске салу механизмі іске қосылады,
- фондық цикл `main.py` ішінде сағат сайын тексеріледі.

## 15. Код сапасын жақсарту (2026 мамыр)

Жаңартылған бөлімдер:

- `handlers/common.py`: `PSYCHOLOG_CHAT_ID` бос болғанда құламау үшін support чаттарын қауіпсіз фильтрациялау;
- `Колледж` бөлімі: заглушка орнына жеке меню және локализацияланған мәтіндер қосылды;
- `services/support_tickets.py`: аноним alias генерациясы `secrets` арқылы жасалады;
- уақыт/SLA өңдеу логикасы біріздендіріліп, дублирлеу азайтылды.

Нәтиже:

- `.env` толық емес конфигурацияда тұрақтылық жоғарылады;
- support модулін кеңейту және тестілеу жеңілдеді;
- университет/колледж UI қабатында қайталанатын код азайды.

## 16. Негізгі мәзір, FSM және Telegram API (2026 мамыр)

- `services/fsm_scope.py`: негізгі мәзірге кіргенде сценарийлерді тазалау (`reset_user_wizard_for_main_menu`), бірақ тіл, трек, reply-якорь және психо-тикет сақталады.
- `utils/main_menu_reply.py`: reply-панельді бір хабарламада жаңарту.
- `utils/safe_telegram.py`: `message is not modified` қатесін бәсеңдету (калькулятор).
- `handlers/staff_cabinet.py`: жеке кабинеттегі инлайн-MVP (`CABINET_WORKPLACE`).
